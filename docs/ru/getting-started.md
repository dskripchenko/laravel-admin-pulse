# Быстрый старт

`dskripchenko/laravel-admin-pulse` — пакет-компаньон `dskripchenko/laravel-admin`.
Ставится один раз, регистрируется сам и появляется в админке.

## Установка

```bash
composer require dskripchenko/laravel-admin-pulse
php artisan migrate
```

## Настройка

```bash
php artisan vendor:publish --tag=admin-pulse-config
```

В `config/admin-pulse.php` — частота сэмплирования по типам, игнорируемые маршруты, сроки хранения, окно дашборда и пороги индикатора.

## Подключение middleware

Пакет регистрирует алиас middleware `pulse`. Добавьте его к маршрутам, которые нужно измерять:

```php
Route::middleware('pulse')->group(function () {
    // ...
});
```

Сэмпл пишется уже после отправки ответа. Запрос ключуется методом и маршрутом, с подставленными параметрами эндпоинта laravel-api — см. [Использование → Сэмплы запросов](usage.md#сэмплы-запросов).

## Что появляется

- Дашборд **«Телеметрия»** (`/admin/dashboard/telemetry`, группа меню «Системные»): плитки с ключевыми цифрами, графики запросов и заданий, таблицы самых медленных маршрутов, самых медленных запросов к БД и самых частых исключений за последние 24 часа. См. [Использование → Дашборд «Телеметрия»](usage.md#дашборд-телеметрия).
- Индикатор в верхней панели — появляется, когда доля ответов 5xx за последние 15 минут превышает порог.
- Ресурс **«Сэмплы телеметрии»** (группа «Системные»): список сырых сэмплов (`admin_pulse_samples`) только для чтения — тип, ключ, метка, длительность, код ответа, время — с фильтрами по типу, ключу (маршрут / отпечаток) и периоду.
- Право `admin.system.pulse.view` — закрывает дашборд, каждый виджет, индикатор и список сэмплов.
- Консольные команды `admin:pulse:aggregate` (агрегаты по окнам в `admin_pulse_aggregates`, по ним строятся графики) и `admin:pulse:rotate` (очистка по срокам хранения).

Поставьте `admin:pulse:aggregate` в планировщик каждые пять минут — без него графики останутся пустыми (таблицы и плитки читают сырые сэмплы и работают в любом случае).
